# Koito SUM v0.1.0-rc.1

First prerelease of **Koito SUM — Simple User Manager**, a fork of
Koito with multiple public listening
profiles and a single administrator account.

## What's included

- Separate listening histories, statistics, rankings, activity, rewind, and now
  playing for each profile.
- Public profile selection at `/`, profile URLs such as `/default`, and a compact
  sidebar selector that preserves the current screen and period when possible.
- Profile creation/editing, photo/icon avatars, key management, deletion, and
  explicit import destinations inside **Settings → Administration**.
- Multiple ingestion API keys per profile. Existing ListenBrainz-compatible
  players continue to use `Authorization: Token ...`.
- Administrator sessions separated from ingestion keys, with origin validation
  for cookie-authenticated mutations.
- One transactional database migration from SQLite schema v2 to v3, with an
  automatic pre-migration backup and preservation of existing tokens/history.
- Docker images for Linux amd64/arm64 and a persistent-volume Docker Compose setup.

## Before upgrading

**Back up your complete data directory and stop the old instance before testing.**
Use the existing `KOITO_CONFIG_DIR` data as the Compose volume. Existing SQLite
v2 installations migrate automatically at startup; administrator credentials
remain unchanged. Experimental SUM databases using the former split v3/v4
migrations must be restored to v2 first. Never edit migration history manually.

## Deploy

```text
ghcr.io/ebrgr/koito-sum:v0.1.0-rc.1
```

Extract the deployment bundle or clone the repository. Copy
`deploy/.env.example` to `deploy/.env`, set the administrator password and the
correct data directory, then run:

```sh
docker compose --env-file deploy/.env -f deploy/compose.yaml pull
docker compose --env-file deploy/.env -f deploy/compose.yaml up -d
```

## Validation and limits

Go tests, TypeScript checks, frontend tests, race checks, and complete API journeys
cover fresh installs, legacy v2 migrations, isolation, concurrent ingestion,
import/export, key revocation, deletion, and restart. The v2 example upgrade
preserved all 72 listens, the old token, administrator password hash, session,
and shared catalog. The integrated Settings UI was checked in desktop Chrome
and at a 400 px viewport.

Profiles and listening data are public to anyone with instance access. The catalog
is shared. Imports are synchronous and can retain partial writes after an error.
This prerelease is intended for testing with backed-up data; migration rollback
requires restoring the previous backup.

Approximately 70% of the work on these SUM changes was done with assistance from
OpenAI Codex. Upstream Koito authorship and licensing remain unchanged.
